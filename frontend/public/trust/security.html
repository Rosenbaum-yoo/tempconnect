Infrastruktur & Verschluesselung

Transportverschluesselung

Alle Verbindungen zwischen Browser und Plattform werden ueber TLS (HTTPS) verschluesselt. Passwoerter werden mit bcrypt gehasht und niemals im Klartext gespeichert. Sensible Daten werden ausschliesslich verschluesselt uebertragen.

Hosting in Deutschland

TempConnect wird in Rechenzentren der Hetzner Online GmbH in Deutschland betrieben. Alle Daten bleiben innerhalb der Europaeischen Union. Mit unseren Infrastruktur-Partnern bestehen Auftragsverarbeitungsvertraege (AV-Vertraege) gemaess Art. 28 DSGVO.

Security Headers

Die Plattform setzt aktuelle HTTP-Security-Headers mittels Helmet.js:

  • Strict-Transport-Security (HSTS) — erzwingt HTTPS
  • X-Frame-Options: SAMEORIGIN — Clickjacking-Schutz
  • X-Content-Type-Options: nosniff — MIME-Sniffing-Schutz
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy: keine Kamera, kein Mikrofon, keine Geolocation
  • CSRF-Token-Validierung bei allen schreibenden Operationen

Multi-Tenancy & Organisationsisolation

Mandantentrennung

TempConnect ist eine Multi-Tenant-Plattform, auf der konkurrierende Organisationen (Personaldienstleister, Entleiher) dieselbe Infrastruktur teilen. Strikte Datenisolation stellt sicher, dass Organisation A niemals Daten von Organisation B einsehen oder aendern kann.

  • Jede Datenbankabfrage wird automatisch auf die aktive Organisation gefiltert (org_id Boundary)
  • Org-Context-Middleware validiert UUID-Format und prueft Mitgliedschaft vor jedem Request
  • Explizite org_id-Header werden gegen die Org-Membership des Users geprueft — Manipulation wird abgelehnt
  • Session-Caching fuer Org-Kontext minimiert Datenbankabfragen ohne Sicherheitseinbussen

Ressourcen-Eigentum (IDOR-Schutz)

Jeder Zugriff auf eine Ressource (Anfrage, Angebot, Stundenzettel, Rechnung) wird gegen den Eigentuemer geprueft. Direkte Objektreferenzen (IDOR) werden durch Ownership-Checks auf Datenbankebene abgesichert.

  • User B kann nicht auf Ressourcen von User A zugreifen, selbst wenn die ID bekannt ist
  • Cross-Tenant-Zugriffe werden automatisch blockiert und protokolliert
  • Deterministische Security-Regression-Tests decken alle Angriffsvektoren ab

Rollenbasierte Zugriffskontrolle (RBAC)

Rollen & Berechtigungen

TempConnect implementiert ein feingranulares RBAC-System mit ueber 15 Rollentypen. Jede Rolle definiert praezise, welche Aktionen ein Benutzer innerhalb seiner Organisation ausfuehren darf.

  • Owner — Vollzugriff inkl. Organisation verwalten, Mitglieder einladen
  • Admin — Konfiguration, Benutzerverwaltung, Audit-Einsicht
  • Program Manager — Anfragen, Matching, Vertragssteuerung
  • Viewer — Nur-Lese-Zugriff auf Dashboards und Reports
  • Supplier-Rollen — Account Manager, Dispatcher, Recruiter mit spezifischen Rechten

Permission-basierte Middleware

Jeder API-Endpunkt ist durch eine oder mehrere RBAC-Middleware-Ebenen geschuetzt:

  • requireAuth — Session-Validierung (401 bei fehlender Authentifizierung)
  • requireOrgContext — Org-Mitgliedschaft erforderlich (403 bei fehlendem Kontext)
  • requirePermission — Feingranulare Berechtigungspruefung (z.B. requisition.create)
  • requireRole — Rollenpruefung fuer administrative Endpunkte
  • Fehlermeldungen sind sanitized (SEC-003) — keine internen Rollen- oder Berechtigungsnamen

Eskalationsschutz

Vertikale und horizontale Privilegien-Eskalation werden aktiv verhindert:

  • Viewer/Member koennen sich nicht zu Admin/Owner-Operationen eskalieren
  • Benutzer ohne erforderliche Permission werden an geschuetzten Endpunkten blockiert
  • Dedizierte Security-Tests fuer jeden Eskalationsvektor (role-escalation, permission-bypass)

Audit Logging & Protokollierung

Append-Only Audit Log

Alle geschaeftsrelevanten Aktionen werden in einem unveraenderlichen Audit Log mit Zeitstempel, Akteur, Organisation und Kontext protokolliert. Audit-Eintraege koennen weder aktualisiert noch geloescht werden.

  • 10+ Aktionstypen: CREATE, UPDATE, DELETE, STATUS_CHANGE, LOGIN, ROLE_CHANGE, PERMISSION_CHANGE, APPROVAL, SUBMISSION, SECURITY, CONFIG_CHANGE
  • Status-Tracking: SUCCESS, DENIED, FAILED
  • Vollstaendige Request-Metadaten: IP-Adresse, User-Agent, Correlation-ID
  • Diff-Tracking: Alte und neue Werte bei Aenderungen werden gespeichert

DSGVO-konforme Datenbereinigung

Vor dem Schreiben in den Audit Log werden sensible Daten automatisch gefiltert. Felder wie Passwoerter, Tokens, IBAN, Kreditkartennummern und Session-Daten werden als [REDACTED] maskiert — niemals im Klartext gespeichert.

  • Regex-basierte Erkennung sensibler Schluesselwoerter
  • Rekursive Bereinigung verschachtelter Objekte
  • User-Kontext in Monitoring nur als anonyme ID (kein Name, keine E-Mail)

Audit-Abfragen & Transparenz

Kunden mit individuellem Tarif erhalten Zugriff auf umfassende Audit-Abfragen mit Filtern nach Akteur, Organisation, Entitaetstyp, Aktion und Zeitraum. Pagination und Export-Funktionen ermoeglichen effiziente Compliance-Reviews.

  • Org-scoped Queries — jede Organisation sieht nur eigene Events
  • Ressourcen-Historie: Letzte Aenderungen an Stundenzetteln, Anfragen, Rechnungen
  • Admin-Panel mit Echtzeit-Filterung und Sortierung

Monitoring & Alerting

Sentry Error Monitoring

TempConnect nutzt Sentry v9 fuer Echtzeit-Fehlererkennung. Jeder unbehandelte Fehler wird automatisch erfasst, kategorisiert und dem Entwicklungsteam gemeldet.

  • PII-Schutz: sendDefaultPii deaktiviert, Cookies/Auth-Header/CSRF-Tokens werden vor dem Versand entfernt
  • Request-Body wird niemals an Sentry gesendet (koennte Passwoerter oder PII enthalten)
  • Correlation-ID und Org-ID als Tags fuer schnelle Fehlereingrenzung
  • Noise-Filtering: Netzwerk-Rauschen (ECONNRESET, EPIPE) wird ignoriert

Prometheus Metriken

Prometheus-kompatible Metriken werden ueber prom-client bereitgestellt. Dies ermoeglicht Echtzeit-Ueberwachung von Request-Latenz, Fehlerquoten, Datenbankverbindungen und Geschaeftsmetriken.

  • HTTP-Request-Metriken: Dauer, Status-Codes, Endpunkt-Verteilung
  • Datenbank-Pool-Metriken: aktive Verbindungen, Warteschlange, Timeouts
  • Geschaeftsmetriken: Matching-Erfolgsrate, Stundenzettel-Durchsatz

Service Health Checks

Automatisierte Health Checks ueberwachen alle Plattform-Komponenten in Echtzeit:

  • API-Server: Erreichbarkeit und Antwortzeit
  • Datenbank: Connection Pool, Migration-Status
  • Redis/Queue: Verfuegbarkeit, Ping-Latenz
  • Matching Engine, Stundenzettel-Verarbeitung, Benachrichtigungssystem
  • Oeffentliche Statusseite unter /status

Incident Response

Incident-Response-Prozess

TempConnect folgt einem strukturierten Incident-Response-Prozess bei Sicherheitsvorfaellen:

  • Erkennung — Automatische Alerts ueber Sentry, Prometheus und Health Checks
  • Klassifizierung — Einstufung nach Schweregrad (P1–P4)
  • Eindaemmung — Sofortige Isolation betroffener Systeme
  • Behebung — Ursachenanalyse und Patch-Deployment
  • Kommunikation — Betroffene Kunden werden ueber die Statusseite und per E-Mail informiert
  • Post-Mortem — Dokumentation und praventive Massnahmen

⏱ Reaktionszeiten

Definierte Reaktionszeiten je nach Schweregrad:

  • P1 (Kritisch) — Plattform nicht erreichbar: Reaktion innerhalb 30 Minuten
  • P2 (Hoch) — Kernfunktion eingeschraenkt: Reaktion innerhalb 2 Stunden
  • P3 (Mittel) — Teilfunktion betroffen: Reaktion innerhalb 8 Stunden
  • P4 (Niedrig) — Kosmetisch/Minor: naechster Arbeitstag

Upload-Sicherheit

Datei-Upload-Schutz

Dokumente (Compliance-Nachweise, Stundenzetteln, Vertraege) werden ueber einen abgesicherten Upload-Prozess verarbeitet:

  • Dateigroesse-Limits verhindern Denial-of-Service durch ueberdimensionierte Uploads
  • MIME-Type-Validierung — nur erlaubte Dateitypen (PDF, PNG, JPG, XLSX) werden akzeptiert
  • Dateien werden im Org-Kontext gespeichert — Cross-Tenant-Zugriff ist nicht moeglich
  • Upload-Aktionen werden im Audit Log protokolliert
  • Rate Limiting pro Benutzer und Organisation schuetzt vor Missbrauch

Security by Design

Architektur-Prinzipien

Sicherheit ist kein Zusatzfeature, sondern in die Architektur eingebaut:

  • Defense in Depth — Mehrere Sicherheitsschichten: TLS, Helmet, CSRF, RBAC, Org-Isolation
  • Least Privilege — Jede Rolle erhaelt nur die minimal notwendigen Berechtigungen
  • Fail Secure — Bei Fehlern wird der Zugriff verweigert (403), nicht gewaehrt
  • Input Validation — Alle Eingaben werden serverseitig validiert und sanitized
  • Idempotenz-Schluessel — Schreibende Operationen sind idempotent, um Duplikate zu vermeiden

Automatisierte Sicherheitstests

Eine umfassende Security-Regression-Test-Suite schuetzt gegen die gefaehrlichsten Angriffsklassen:

  • Auth Security — Unauthentifizierter Zugriff auf geschuetzte Endpunkte
  • RBAC Security — Versehentliche Entfernung von RBAC-Guards
  • Org Isolation — Cross-Tenant-Zugriff (Org A liest Daten von Org B)
  • Resource Ownership — IDOR-Angriffe (User B greift auf Ressourcen von User A zu)
  • Role Escalation — Vertikale Privilegien-Eskalation
  • Permission Bypass — Horizontale Privilegien-Eskalation
  • 70%+ der Tests sind Negativ-Tests: sie pruefen, dass unauthorisierter Zugriff blockiert wird

DSGVO-Konformitaet

TempConnect verarbeitet personenbezogene Daten ausschliesslich auf Grundlage der DSGVO. Wir erheben nur die fuer den Plattformbetrieb erforderlichen Daten.

  • Datenminimierung als Grundprinzip
  • Keine Weitergabe an Dritte ausserhalb der Plattform
  • Kontaktdaten erst nach Deal-Abschluss freigegeben
  • Vollstaendige Datenschutzerklaerung unter /datenschutz
